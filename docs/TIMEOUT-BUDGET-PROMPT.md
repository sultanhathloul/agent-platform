IMPLEMENTATION CHOICES ALREADY MADE (record as ADRs, status decided; do not reopen):
- I1. Deadline mechanism: anyio cancel scopes (fail_after / move_on_after) and anyio.current_effective_deadline(), wrapped in one small helper module app/resilience/deadline.py (bounded(ceiling_s) → min(ceiling, remaining − margin)). Alternatives to name in the ADR: asyncio.timeout (no effective-deadline lookup across nesting), a custom contextvar stack (custom code where a maintained library fits, rule 12i). Add the row to docs/RESILIENCE.md "What we built".
- I2. Whole-turn deadline in a new config/turn.yaml: deadline_s 120, answer_reserve_s 45, evidence_fetch_s 10, gateway_margin_s 15. The runner opens the turn scope; each capability runs under min(manifest timeout_s, remaining − answer_reserve_s); the evidence fetch under min(evidence_fetch_s, remaining − answer_reserve_s), on timeout its sources stay without text by code (the existing failure path); the answer under what remains. At the deadline the turn ends with error code turn_timeout through the existing terminal-error path (same persistence as other terminal errors), the conversation lock is released in a finally, and every task the turn owns is cancelled; work that belongs to no caller (ADR-0245 status reads, a background registration of I5) is untouched.
- I3. Gateway: the SSE relay gets one total bound, deadline_s + gateway_margin_s (135 s), read from config/turn.yaml through the same mechanism that reads config/docs.yaml; past it the relay ends the stream with turn_timeout and closes the agent connection. The 60 s response-header timeout stays. Before changing anything, establish with a test what ends a stream at 60 s today (phase 05 lost cases at "the 60 s gateway timeout" although the table says headers only) and record the finding in docs/RESILIENCE.md.
- I4. Model calls (config/models.yaml, new key timeouts): helper roles (router, summarizer, judge, extractor) 20 s; reasoning and reflection 90 s; embeddings for a query 15 s, for an ingest batch 60 s; rerank 20 s; each bounded by what remains of the enclosing scope. The wall-clock deadline covers send to last chunk; the OpenAI and httpx per-operation timeouts are set 1 s above it so the deadline always decides. LiteLLM: num_retries 0; request_timeout 85; the agent passes a per-request timeout of remaining − 1 s. Retries move to the agent: at most one, only before the first streamed token, only on 429, 5xx or a connection error, only when ≥ 10 s remain, backoff uniform 0.5–1.5 s. The heavy → standard fallback stays; a test proves the whole call, fallback included, ends by the agent's deadline and that LiteLLM closes the upstream request when the agent cancels. If LiteLLM cannot be made to close it, record the residual in docs/RESILIENCE.md, bounded by request_timeout, with the test showing the bound.
- I5. MCP upload registration: config/docs.yaml register_response_s 20. Past it the upload answers with the attachment `pending`; the registration goes on in the background within the server's semaphore and timeout_s, at most one per attachment, its outcome kept on the record; a failure sets `failed` with code register_failed. Registration is idempotent on the attachment id. Search drops hits from an attachment whose record is failed. Tested: a server that registers in 25 s → the upload answers pending in ≤ 20.5 s, the record turns indexed; a server that fails → failed, its chunks never returned.
- I6. MCP call (app/mcp/client.py, broker): broker bound = min(2 × timeout_s + 2, remaining), matching ADR-0237's text; semaphore wait ≤ min(timeout_s, remaining − timeout_s − 1), and when that is ≤ 0 the call fails tool_busy at once with the breaker untouched; one attempt deadline covering session open and send, min(timeout_s, remaining − 0.5); the I9 re-send and its connected.wait() live inside that same attempt deadline; SDK read_timeout_seconds = timeout_s + 1, so the transport deadline always decides.
- I7. Sandbox memory (ingest and mcp-rag-ref): measure the peak RSS of one sandbox child on the phase 04 test corpus and of the parent under two concurrent jobs. If 2 × the child's peak ≤ 640 MiB, set the child limit to 640 MiB and keep mem_limit 2g; otherwise keep 1024 MiB and set mem_limit to workers × child + parent reserve (measured parent peak × 1.5, at least 512 MiB), rounded up to 256 MiB. At startup each service reads its cgroup memory.max and refuses to start, with a clear log line, when workers × child limit + reserve exceeds it. Record the measurements and the resulting Docker Desktop memory figure in PROGRESS.
- I8. Keep-alive: uvicorn --timeout-keep-alive 75 in the agent; the gateway's JDK HttpClient idle set explicitly to 30 s (jdk.httpclient.keepalive.timeout), after checking the effective value of the JDK in the image. Client idle 30 s < server idle 75 s.
- I9. scripts/check_timeout_budget.py reads config/turn.yaml, config/models.yaml, config/docs.yaml, config/mcp.yaml, every capability manifest, infra/litellm/config.yaml, the gateway's application.yml and the agent's Dockerfile, and fails when any nested pair of docs/RESILIENCE.md has inner ≥ outer. make test runs it; report it as its own line, "timeout budget N / 0 / 0".
