DECISION (owner, record as ADR, decided): the platform's capacity and timeout settings are managed by the platform administrator from the web UI, with the files as defaults; the same page shows the timeout tree and live usage, read-only.

1. Editable from the UI:
   - config/turn.yaml: per_user_max, per_tenant_max (default none) with per-tenant overrides by tenant id, deadline_s, answer_reserve_s, post_answer_reserve_s, evidence_fetch_s.
   - config/models.yaml timeouts: helper, reasoning, embed_query, embed_batch, rerank.
   - config/docs.yaml: concurrent uploads per user and per tenant, uploads per minute per user, register_response_s.
   - config/mcp.yaml max_concurrency per server: may be lowered, never raised above the file's value (the ICD figure).
2. Shown read-only, with their source and the note that a change needs a redeploy: LOCK_POOL_SIZE, the ingest and mcp-rag-ref container limits and sandbox child limit, gateway_margin_s, keep-alive values.
3. Storage: the files stay the defaults and are validated at startup as today. Overrides live in a new append-only table of versions (follow the guard policies pattern: every save is a new version, revert is a new version, no deletion, ADR-0166), reloaded in the agent through Redis pub/sub. The gateway reads the effective values it enforces (upload caps, turn stream bounds) from an internal agent endpoint, cached at most 10 s. A change applies to requests that start after it; in-flight requests keep their values. Hot paths read the cached values, never the DB per request; if Redis or the DB is down the last known values stay in force. A stored override that fails validation at startup (for example after a file default changed) is ignored, the file value used, and an error logged.
4. Validation on save: the shared validator app/resilience/budget.py, used by scripts/check_timeout_budget.py and by the save endpoint, holding the nested pairs and ranges (inner < outer, positive, sane maximums), including the rules it generates per capability manifest. An invalid save is refused, with an Arabic and English message naming the conflict in plain words (for example "مهلة الإجابة أطول من مهلة السؤال كله"). The save shows the effective values a change would produce before it is confirmed.
5. Access and audit: admin role only (ADR-0117), checked at the gateway AND the agent. Every change is audited fail-closed with before and after values and the actor's username and display name (the policy change log precedent).
