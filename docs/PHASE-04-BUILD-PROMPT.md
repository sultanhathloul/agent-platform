IMPLEMENTATION CHOICES ALREADY MADE (record as ADRs, status decided; do not reopen)
I1. Upload goes through the gateway (multipart, streamed to MinIO bucket uploads), not browser-to-MinIO pre-signed URLs: limits, ownership and audit are enforced server-side and MinIO stays internal. Every upload, download, status read and delete is audited fail-closed (ADR-0042).
I2. Ingestion runs in a background worker inside the agent service (Redis queue), capability-agnostic, in rag/ingest/. A job is idempotent by attachment id, resumes after a crash, and a failure carries a reason code.
I3. One chunk table agent.rag_chunks (collection, attachment_id, user_id, tenant_id, page, section, ord, text, text_norm, tsv, embedding, expires_at). collection = sess_{conversation_id} now, kb_{slug} in phase 05. Every query names the collection and the owner. VectorStore is the only reader and writer.
I4. Full text: tsvector with the simple configuration over text normalized by app/text/arabic.py (alef, yaa and taa marbuta folding; tatweel and tashkeel removed; light prefix stripping), so Arabic matching is deterministic.
I5. Hybrid retrieval: top 30 by vector and top 30 by text, fused by reciprocal rank fusion, reranked, top 8; compression per README §7 step 6 when over budget. Values in config/docs.yaml.
I6. Reranker: bge-reranker-v2-m3 served by a local rerank server container behind the LiteLLM rerank alias. Choose Infinity or Hugging Face TEI by what the pinned LiteLLM /rerank supports, and record which. Weights are fetched by make models into a volume, never at container start. A rerank call, like an embedding, is not a chat call and takes no ContextPackage (ADR-0058 precedent). Measure rerank latency on the dev host and record it.
I7. Extraction: PDF per page with a permissively licensed library (no AGPL); NFKC to fold Arabic presentation forms; detect visual-order Arabic lines and restore logical order; DOCX by headings; XLSX per sheet with the header row repeated in each chunk; TXT and MD heading-aware. Chunking per §9.3: recursive, 800 tokens, 120 overlap.
I8. Retrieval is a tool of the docs capability, executed by the broker. Chunks pass POST_TOOL (sanitize_untrusted first, §10.3) and reach the model inside untrusted-data delimiters. A document that says "ignore your instructions" is data.
I9. Langfuse (D5 precedent): retrieval spans carry attachment ids, pages, scores and token counts, never chunk text. Uploaded content never leaves the platform through traces.
I10. Status: the attachment record holds pending | indexed | failed (+ reason). The web polls the status through the gateway every 2 s until terminal. The send button stays disabled while an attached file is pending.
I11. Routing: the attachments rule selects docs on the turn a file is attached. On later turns of a conversation with indexed files, the router model (role router, fast tier, ADR-0015) chooses between docs and general, cached by hash for 1 h. evals/golden/routing.jsonl starts here with at least 30 docs/general cases, Arabic and Gulf included; threshold 0.90.
I12. Citations: {attachment id, file name, page or section, chunk id}. validate fails an answer that cites a chunk not retrieved in this turn. The UI opens a preview panel with the cited chunk and its page, and a download through the gateway (owner only).
I13. rag.jsonl: at least 40 cases over at least 4 generated Arabic documents (one DOCX with headings, one XLSX, one multi-page PDF, one PDF with fake PII). Ragas scoring calls LiteLLM's judge alias; the eval harness is a client, not an agent model call. Record this interpretation of rule 6 in an ADR.
I14. Agent and gateway OpenAPI move to 1.4.0 once for the whole phase.
I15. Test embeddings and rerank: infra/litellm/config.mock.yaml returns one fixed vector for every text, so retrieval ranking cannot be tested with it, and it has no rerank alias. Add a small deterministic test-only service behind the mock LiteLLM config for the embed and rerank aliases: hashed bag of normalized words (app/text/arabic.py) for embeddings, word overlap for rerank scores.
