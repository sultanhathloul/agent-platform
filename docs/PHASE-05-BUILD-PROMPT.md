I1. DocumentScope generalised (BACKLOG item 10): a scope names tenant, user and a list of collections. A capability's manifest declares which collection kinds it reads (documents.collections: [session] for docs); the broker intersects, so docs never sees a kb collection. Source gains backend and collection; graph/evidence.py fetches each source through the backend and collection that found it. RuntimeContext carries the backends by name; config/<slug>.yaml names the one a capability uses. The citation event, done.citations and the citations persisted on replies (ADR-0193) keep their shape: backend and collection stay internal. Tested with the in-memory fake backend holding a kb_ collection: permitted and selected → found; not permitted, or not selected → nothing, by any reference; and a conversation persisted before this change reopens with its citations (G9).
I2. Transport: MCP Streamable HTTP only, with the official Python mcp SDK pinned to an exact version (record it). stdio is refused by config validation: the agent spawns no server process. Server-initiated features are refused: sampling, elicitation, roots; resources and prompts are not read; tools/list_changed is ignored.
I3. config/mcp.yaml per server: id (logical, stable: routing, rag), url_env (the URL comes from .env), auth (none | bearer_env: the token's env variable name), internal: true|false, profiles where enabled, timeout_s (default 10), max_result_bytes (default 262144), max_concurrency (default 8), and tools: [{name, remote_name, risk: read, label {ar, en}, input_schema_sha256, injected {field: principal.tenant_id | principal.user_id | scope.collections}}]. Secrets only in .env.
I4. Broker tool names are {server}.{tool} (routing.geocode); the policy scope is tool:{server}.{tool}, and tool:{server}.* matches every tool of a server. A capability declares them in its manifest tools list like any tool.
I5. Schema pinning: at startup and on reconnect the client lists the server's tools and compares each allowlisted tool's input schema hash with input_schema_sha256. A mismatch or a missing tool disables that tool (fail closed, logged, shown in /v1/health); the others work. A make target prints the current hashes for the owner to review into the config.
I6. Injected fields are filled by the broker from the principal and the scope, removed from any schema a model sees, and a call whose arguments name one is refused (ADR-0160 precedent).
I7. Results: structuredContent when present, else the text parts; images, audio, resource links and embedded resources are dropped with a note. The size cap is enforced while reading the HTTP body (tool_result_too_large, no parse beyond the cap). Results reach the model only through POST_TOOL (sanitize_untrusted first) inside the untrusted delimiters in the user role (ADR-0165). No caching of MCP results.
I8. Resilience: per-server semaphore (max_concurrency), per-call timeout, circuit breaker (5 consecutive failures → open 30 s → half-open probe). An unavailable, timed-out or open-circuit call returns tool_unavailable / tool_timeout to the capability, which states it in its findings; the turn continues. The agent starts and make up stays green when a server is down; it reconnects with backoff. /v1/health lists each server and disabled tool, content-free. Error codes with Arabic and English messages in errors.yaml, the gateway catalogs, ar.json and en.json.
I9. MCP sessions are pooled per server and carry no per-user state: every call carries all it needs. The session is re-initialised on expiry.
